# Oilpuz 기획서 v0.1 — 마라탕 한 그릇

작성: 2026-09-29 · 대상: Unity 6000.1.9f1 / URP 2D · 상태: 첫 제작 기준

## 1. 게임 한 문장

마라탕 위에 흩어진 고추기름을 손끝으로 집어 늘이고, 재료 사이로 운반해 한 덩어리로 모으는 세로형 모바일 퍼즐.

## 2. 이번 제작 범위와 순서

기획서 → 생성한 예상 스크린샷 → 화면을 보고 에셋 목록 확정 → 개별 이미지 생성 → Unity 임포트 및 플레이 가능한 씬 구성.

이번에는 마라탕 스킨 한 종류와 핵심 조작을 검토할 수 있는 프로토타입을 만든다. 앱스토어 배포, 광고·결제, 스킨 상점, 전체 레벨 확장은 포함하지 않는다. 향후 스킨을 연결할 수 있는 데이터 구조는 만든다.

## 3. 화면과 아트 방향

- 9:16 세로 화면, 위에서 정면으로 내려다보는 정투영 구도.
- 따뜻한 아이보리 식탁, 붉은 고추기름, 적갈색 마라 국물, 옥색 포인트. 음식점 메뉴처럼 정돈된 UI.
- 중앙의 큰 도자기 그릇이 주 플레이 영역. 음식은 먹음직스럽게 표현하되 조작 가능한 기름의 윤곽은 선명하게 구분한다.
- 기름: 밝은 호박색~고추기름 주황색, 얇고 반투명한 막, 가장자리 반사. 젤리 구슬처럼 과도하게 두껍게 표현하지 않는다.
- 장애물은 마라탕 재료: 버섯/완자 등. 대파, 고추 등 장식은 충돌하는 재료와 배치·대비로 구분한다.
- 상단: 브랜드/스킨명, 스테이지 이름, 남은 덩어리, 허용 갈라짐.
- 하단: 손끝 장력 표시, 상황별 한 줄 안내, 재시작/일시정지, 5단계 선택.
- 목표 지점은 밝은 옥색 점선 원. 재료와 기름에 가려지지 않는 윤곽으로 표시.
- 문 가까이에서 너무 커지면 '작은 방울부터 건너세요' 안내. 처음에 단순히 못 움직이는 것으로 보이지 않아야 한다.

## 4. 반드시 구현할 손맛

### 누른 지점을 잡는 조작

1. 손가락이 실제 기름 표면에 닿은 위치를 찾는다.
2. 그 주변의 소수 입자를 잡고, 눌렀던 위치와 입자 사이의 오프셋을 유지한다.
3. 드래그 목표는 그 입자에 국소적으로 전달한다. 덩어리 중심을 손가락 위치로 옮기지 않는다.
4. 앞부분이 먼저 움직이고 뒤쪽은 점성·표면장력으로 지연되어 따라온다. 모양은 비대칭으로 늘어나고 목이 만들어진다.
5. 손을 놓으면 형태가 천천히 이완된다. 지나치게 탄성 있는 고무처럼 튀지 않는다.
6. 과한 장력은 입자 연결을 끊어 두 덩어리로 분리한다. 클릭 자체나 단순 프레임 지연은 분열을 발생시키지 않는다.

### 내부 모델

- 고정 시간 간격의 2D 입자/제약 모델. 입자별 면적은 유지한다.
- 근거리 반발, 응집, 점성 감쇠, 연결 제약으로 퍼짐과 압축을 제한한다.
- 잡은 물질 입자는 식별자를 유지한다. 이동 중 가장 가까운 다른 입자로 계속 갈아타지 않는다.
- 과도한 변형을 받은 연결을 절단하고 연결 성분을 계산해 실제 분열을 판정한다.
- 서로 닿은 재료 그룹은 인접 연결을 형성해 합쳐진다. 합체 후에도 잡은 위치의 입자가 유지된다.
- 렌더링은 입자의 밀도장을 합치는 메타볼 셰이더. 이미지를 늘이는 방식으로 유체를 흉내 내지 않는다.
- 모바일 프로토타입은 수십~100여 입자부터 시작하고, 밀도장은 낮은 해상도 RenderTexture에 누적한다. 최종 성능은 실기기로 측정한다.
- 정밀 유체 해석이 아닌 게임용 근사 모델이다. 이 제약은 외형, 손맛, 퍼즐 예측 가능성을 우선한다.

## 5. 퍼즐 규칙

- 모든 기름 입자를 하나의 연결된 덩어리로 합친다.
- 덩어리 전체가 목표 원 안에 들어간 상태에서 손을 놓고 잠시 안정되면 클리어.
- 단계별 갈라짐 허용 횟수를 넘기면 실패. 즉시 재시작 가능.
- 시간제한은 없다. 실패해도 광고나 대기 없이 다시 도전.
- 좁은 길은 작은 덩어리를 먼저 옮기도록 유도한다. 입자의 탄성 압축으로 대형 덩어리가 무한히 가늘어져 문을 우회하지 않도록 응집과 면적 유지, 큰 덩어리의 통과 제한을 함께 조율한다.
- 큰 덩어리의 어려움은 입력 지점 뒤에 따라오는 물질의 양과 장력에서 생긴다.

## 6. 초기 5단계

| 단계 | 이름 | 배울 것 | 갈라짐 허용 |
|---|---|---|---|
| 1 | 첫 숟가락 | 국소 드래그, 합치기, 목표 원 안착 | 2 |
| 2 | 재료 사이로 | 재료를 우회하는 경로와 늘어나는 꼬리 | 2 |
| 3 | 모으기 전에 | 좁은 문을 건넌 뒤 합치는 순서 | 1 |
| 4 | 국물의 흐름 | 약한 물살과 손끝 장력 조절 | 1 |
| 5 | 한 번도 흩어지지 않게 | 가장 좁은 문, 물살, 0회 분열 | 0 |

웹 버전의 원형 덩어리 수치와 좌표는 그대로 복사하지 않는다. 새 변형 모델에서 통과 가능성과 난이도를 검증해 배치한다. 모든 단계를 자유 선택 가능하게 하여 프로토타입 검토를 돕는다.

## 7. 스킨 구조

`SoupSkin` ScriptableObject: id, 표시명, 테이블 이미지, 국물/그릇 이미지, 재료 스프라이트 목록, 국물색, 기름색/윤곽색/하이라이트, UI 강조색.

`StageDefinition`: 입자 초기 그룹, 충돌체와 재료 선택, 목표 원, 갈라짐 예산, 물살. 스킨은 규칙이나 통과 폭을 바꾸지 않는다. 동일 충돌체에 이미지 크기와 회전을 맞춘다.

마라탕: 고추기름+도자기+버섯/완자. 짬뽕과 라멘은 이후 동일 필드에 다른 이미지와 색을 연결한다. 미완성 스킨을 완성된 것으로 표시하지 않는다.

## 8. 생성 이미지 원칙

- 예상 스크린샷은 비주얼 방향을 확인하는 컨셉 이미지이며 실제 Unity 실행 캡처와 별도로 보관한다.
- 스크린샷을 확인한 뒤 필요한 에셋을 `Docs/Art/AssetManifest.md`에 확정한다.
- 식탁, 그릇과 국물, 재료를 분리 생성한다. 이미지 속 UI 글씨를 실제 버튼으로 사용하지 않는다.
- 모든 프롬프트와 결과 경로를 저장한다. 투명 스프라이트는 실제 알파 채널을 사용한다.
- UI 아이콘, 목표 링, 기름, 장력 게이지는 코드/셰이더로 표현한다.

## 9. 검수 기준

- 가장자리를 집으면 그쪽이 먼저 늘어나고 반대쪽은 지연되어 따라온다.
- 누르는 순간 중심이 튀지 않고 합쳐진 뒤에도 잡은 물질을 놓치지 않는다.
- 느린 드래그에서는 하나로 유지되고 과도한 드래그에서 실제로 연결이 나뉜다.
- 분열·합체 전후 입자 수와 면적이 보존된다.
- 장애물을 통과하지 않으며 목표 밖이나 드래그 중에는 클리어되지 않는다.
- 생성 에셋이 실제 씬에 연결되고 한국어 글자가 깨지지 않는다.
- 화면비가 달라도 그릇·입력 좌표가 일치하고 UI가 잘리지 않는다.
- 검증을 실제 수행한 범위와 남은 한계는 `Docs/Validation.md`에 구분해 기록한다.
