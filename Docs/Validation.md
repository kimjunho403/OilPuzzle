## 수행 완료

### 2026-09-29 실제 입력 오류 수정

- 최초 30개 검사와 캡처 데모는 UI 이벤트 핸들러를 직접 호출해 실제 클릭 경로의 오류를 검출하지 못했다.
- `UICard`/`UIRing`에 `CanvasRenderer`가 없어 `GraphicRaycaster`가 예외를 내고 모든 포인터 입력을 중단했다. 두 클래스에 `RequireComponent`를 추가하고 기존 MalaPuzzle 씬의 누락 컴포넌트도 복구·저장했다.
- Play 모드에서 `Oilpuz > Repair and validate UI input` 검사 통과: 기름 영역과 모든 활성 버튼에 `EventSystem.RaycastAll` 도달.
- 가상 Mouse 장치의 상태를 프레임별로 Input System에 주입해 실제 UI 모듈을 통한 잡기, 45프레임 이동, 놓기 통합 검사 통과 (`OILPUZ_MOUSE_DRAG_OK`). 핸들러 직접 호출 없이 검증했다.
- Windows UI 자동화로 실제 기름 클릭과 스테이지 선택/재시작 버튼 확인. 자동화 도구의 짧은 drag는 한 프레임으로 합쳐져 이동 검증에는 위 통합 검사를 사용했다.
- 수정된 에디터 Play 모드를 실행해 둠. 기존 Windows exe와 아래 과거 캡처는 이 수정 전 결과이며 이번에 재빌드하지 않았다.

- Unity에서 C# 컴파일 성공.
- `OilpuzProjectBuilder.Validate`의 실제 엔진 내 검증 **30개 통과**. 원문은 `Validation-results.txt`.
- 원본 PNG 다섯 장을 프로젝트에 저장, 4개 투명 스프라이트의 RGBA/모서리 알파 0 확인.
- Mala SoupSkin, 5개 StageDefinition, 게임 씬의 이미지·폰트·셰이더 참조 연결.
- 두 커스텀 셰이더 컴파일 오류 없음.
- Windows 개발 빌드 성공: `Builds/Windows/Oilpuz.exe`.
- 실제 플레이어의 카메라 렌더를 540×960 PNG로 저장하고 육안 점검. 생성한 예상 화면과 구분.

## 물리와 조작 확인

- 기름 표면의 실제 누른 부분을 잡을 수 있음.
- 눌렀을 때 중심이나 입자가 순간 이동하지 않음.
- 초기 느린 드래그 20스텝에서 앞부분 이동 0.0751, 반대편 0.0277: 국소 움직임이 먼저 발생함.
- 드래그와 합체 후에도 잡은 입자 식별자가 유지됨.
- 느린 드래그는 연결 유지, 빠른 당김은 실제 연결 그래프의 목 절단으로 분열.
- 합체와 분열 중 입자 수/물질 면적 보존.
- 허용 횟수 초과 시 실패 및 정지, 재시작 시 해제.
- 국소 입력을 강하게 움직여도 재료 충돌체를 관통하지 않음.
- 원 밖의 단일 덩어리는 클리어되지 않음. 원 안의 단일 덩어리를 놓고 기다리면 클리어.
- 5개 단계의 시작 입자가 그릇과 재료를 침범하지 않고 초기 연결 성분이 안정적임.

## 실제 렌더 캡처

- `Art/ActualGame-Stage01.png`: 마라탕 아트·한국어 UI·기름·목표 원.
- `Art/ActualGame-LocalDrag.png`: UI의 포인터 수신 컴포넌트를 통해 가장자리를 당기는 장면. `.png.json`에 잡은 입자, 장력, 물질 수 기록.
- `Art/ActualGame-Stage05.png`: 7개 방울과 좁은 재료 통로, 0회 갈라짐 HUD.

발견 및 수정: Direct3D 렌더 텍스처의 상하 방향 차이로 기름 표시가 입력 좌표와 뒤집히는 문제를 셰이더에서 교정. UI 텍스처를 표면 재질에도 명시적으로 연결. 손끝 부착과 후행 변형의 차이를 강화. 숨긴 창의 backbuffer 캡처는 검게 나와 URP 직접 카메라 렌더로 검수 방식을 변경.

## 아직 검증하지 않은 항목

- Android/iOS 실기기 플레이, 실제 손가락 입력, 발열과 프레임 시간. iOS 빌드.
- 최종적으로 조정된 5단계 전체의 사람 플레이 및 모든 우회 경로.
- 상용 수준의 물리 정확도나 다양한 휴대폰 GPU에서의 표현 일치.

현재 모델은 입자 기반 게임용 근사다. 큰 덩어리의 통로 통과 제한은 면적 기반 퍼즐 규칙과 입자 충돌을 함께 사용하며, 완전한 유체 해석이 아니다. 이미지와 기본 조작을 함께 검토하는 첫 Unity 프로토타입 범위다.
